# oshicase 企画書

推し活の「現場」を1枚ずつ残す記録帳アプリ。根拠は `reports/推し活アプリ市場調査.md` と `reports/推し活アプリの不満 追加調査.md`。

## 1. ひとことで

**申込から感想まで、現場をまるごと1枚に。入金を流さない。落選も記録に残る。**

- moviecase・clipcase と同じ「case」シリーズとして並べる（名前の検索では同名アプリは見つからず。申請前にストアで再確認）
- 正式名：**oshicase（オシケース）- 推し活の現場記録とカウントダウン**
- 予備の名前：げんば帖 ／ 推しのしおり

## 2. 誰のためか

| 層 | 姿 | このアプリでうれしいこと |
|---|---|---|
| メイン | 年に数回〜十数回ライブ・イベントに行く人（20〜40代が中心） | 当落・入金・発券の締切を落とさない。行った現場が貯まっていく |
| ライト | 現場は年1〜2回、ふだんは配信や記念日を楽しむ人 | ウィジェットで「推して◯日」「誕生日まで◯日」 |
| ヘビー | 遠征・複数の推し・多ジャンル・連番や同行の立替が多い | 名義・立替の管理、推しをまたいだ集計。買い切りで課金してくれる層 |

中央値が年4万円程度のライト層がほとんどなので、**無料で十分に使え、うれしい人だけが買い切りで払う**形にする。

## 3. 競合と、他との違い（売り）

### 競合の状況

- 記念日・ウィジェット系の首位だった Oshibana が閲覧専用になり、乗り換え先を探す人がいる
- **ライブ記録や当落管理の直接の競合はすでにある。** Live Rock、relight、Ainy! などのライブ記録アプリに加え、2026年は個人開発の当落管理アプリ（推しごよみ、推シツジなど）が次々に出ている
- 「広告なし・ログイン不要・バックアップ・買い切り」は、競合の多くが掲げる**標準装備**になりつつある。看板に書くだけでは差にならない
- ステータスごとの締切通知も、すでに複数のアプリにある

### oshicase の売り

差は「書いてあること」ではなく、**実際にそうなっていること**と**後から変えないこと**でつける。

1. **本当に消えない**：データはスマホの中。アップデートの前に自動でバックアップし、「最終バックアップ日時」を見せ、復元できることを自分で確かめられる。ログインは要らない
2. **約束を変えない**：買い切りのまま、サブスクにはしない。広告も出さない。推しの数・現場の数・写真の枚数に制限をかけない。推しカラーはずっと無料
3. **チケットの事故を防ぐ**：事故が起きるのは「当選 → 入金 → 発券・分配」の間。入金締切・分配開始日・名義・申込先を1枚にまとめ、同じ日時の重複申込には警告を出す
4. **立替も分かる**：連番や同室ホテルの「何人分」「うち立替」「回収済み」を記録し、集計は自分の負担分だけ
5. **現場が1枚にまとまる**：申込から写真・セトリ・感想・費用まで同じカードに続く。落選も消さずに残る
6. **入力が軽い**：必須はタイトルと日付だけ。あとから足せる
7. **邪魔しない**：通知は自分で入れた締切と記念日だけ。運営からのお知らせは送らない。アクセス許可は写真と通知だけ

## 4. 画面構成（最初の版）

下のタブは4つ。

### ① ホーム
- 推しの切り替え（上部に推しカラーの丸いアイコン。「すべて」もある）
- **次の現場**カード：「あと12日」「公演名・会場」
- **やることリスト**：近い締切から（「◯◯ 2次抽選の申込 あす23:59まで」「入金 あと2日」「分配開始 11/1 12:00から」）
- 記念日：「推して 1,234日」「誕生日まで 45日」

### ② 現場
- 一覧（これから／行った、の切り替え。月ごとの区切り）
- **落選・見送り・譲渡/取消のカードはグレー表示**にして、「これから」の一覧で当選と見間違えないようにする
- 1枚のカードに推しを何人でも付けられる（共演・箱推し向け）。付けたことが一目で分かる表示にする
- **カードの複製**：ツアーの別公演などは複製して日付と会場だけ変える

#### 現場カード（このアプリの中心）

**必須はタイトルと日付だけ。** ほかはすべて空欄で保存でき、あとから足せる。

ステータス：
`検討中 → 申込済 → 当選 / 落選 → 入金済 → 発券済 → 参戦済`
終わり方として **見送り** と **譲渡・取消** も選べる。

| まとまり | 項目 |
|---|---|
| 基本 | タイトル、日付・開演時刻、会場（自由に書ける。過去に入れた会場を候補に出す）、出演者（空欄でよい）、推し（複数）、**現場の種類**（ワンマン／対バン／フェス／舞台／特典会／番組観覧／ライブビューイング／配信） |
| 申込 | **申込先**、**申込方法**（抽選／先行／一般／リセール）、**名義**、**結果の通知元**（申込先と違うことがある） |
| 締切 | 申込締切、当落発表、入金締切、**分配開始**、発券開始など。それぞれに通知 |
| 当日 | 座席（自由入力）、同行者 |
| 参戦後 | 写真、セトリ、感想、星やスタンプ |
| お金 | 費目（チケット／**手数料**／交通／宿泊／グッズ／その他）と金額。行ごとに**何人分・うち立替・回収済み**のチェック |

- **重複の警告**：同じ日時に「当選」「申込済」の現場があると、申込のときに「この日時は◯◯に当選しています」と出す
- **セトリ**：テキストを貼り付けると1行1曲に分かれる。行の種類（曲／MC／EN／リハ／メドレー）をあとから付けられる。並べ替えもできる
- **お金の集計は自分の負担分だけ**。立替は「未回収 ◯円」としてまとめて見られる
- 「落選」も記録として残る（年間の当選率と「次はどう申し込むか」の相談に使う）

#### 写真

写真をたくさん残したい人に合わせる。

| 方針 | 中身 |
|---|---|
| 枚数 | 制限なし（無料でも） |
| 保存 | アプリの中に圧縮したコピーとサムネイルを保存。スマホの写真を消してもアプリには残る |
| 元の画質 | 設定で「元の画質で保存」も選べる（容量を使うことを表示する） |
| 追加 | 複数まとめて選んで追加できる |
| 並び順 | 入れた順を保つ。並べ替えもできる |
| 共有 | 書き出し・共有のときは位置情報を消す |
| アルバム | 推しごとに、全部の現場の写真を並べて見られる「アルバム」 |
| 動画 | あとの版で対応 |

### ③ カレンダー
- 月のカレンダーに現場・締切・記念日を推しカラーの点で表示（ラビラビのカレンダー部品を流用）

### ④ まとめ（v1.1）
- 今年の現場の数、当選率、行った会場の数、かかったお金（推しごと、費目ごと。自己負担分だけ）
- **年間まとめ画像**：「2026年の推し活　現場 14回／当選率 62％／一番行った会場 ◯◯」を推しカラーで1枚に。SNS で共有（moviecase の共有画像の仕組みを流用）
- 予算：月や年の予算を決めると、残りが出る（家計簿まではやらない）

### 設定

| 項目 | 初期値 | 中身 |
|---|---|---|
| 金額を表示する | オン | オフにすると、一覧・現場カード・まとめから金額と予算が消える。入力済みの記録は消さない。人にスマホを見せるときや、金額を見たくない人向け |
| まとめ画像に金額を入れる | **オフ** | SNSに載せる画像に金額を入れるかどうか。外したときは「行った会場の数」に差し替える |
| まとめ画像に座席・回数を入れる | オン | 座席や参戦回数も画像から外せる（「マウント」と言われたくない人向け） |
| 通知の時刻 | 朝 | 記念日などの通知を何時に出すか。締切の通知はその締切ごと |
| 日数の数え方 | 初日を含める | 含める／含めない、「◯日」表記／「◯年◯か月」表記。ちょうど◯年の日は「4年」と出す |
| 写真を元の画質で保存 | オフ | オンにすると容量が増える |
| バックアップ | オン | iCloud / Google ドライブへ。**写真のバックアップはオン／オフを別に選べる**。「最終バックアップ日時」を表示 |
| 復元の確認 | — | バックアップから実際に戻せるかを確かめられる画面 |
| 書き出し | — | ZIP（写真＋CSV） |
| 購入を復元 | — | サポーターパックを買い直さずに戻す |

### 推しの登録
名前、推しカラー（テーマ色がそれに変わる）、アイコン画像、推し始めた日、誕生日、ほかの記念日（デビュー日など）、**FC更新日**（締切と同じ仕組みで通知）。1分で終わる手軽さを大事にする（乗り換えの人向け）。

### ウィジェット
- 小：「推して◯日」または「◯◯まで あと◯日」
- **ロック画面の小さいウィジェット**：同じ内容
- 推しカラー
- 毎日きちんと更新されることを公開前にテストする（日付が変わったとき、アプリを開いていない日が続いたとき）
- 中・写真入りは v1.2

## 5. データの形（ざっくり）

あとから形を変えると、移行のときにデータが消える危険がある。**v1.0の時点で次の形にしておく。**

- **推し**：id、名前、色、画像、記念日のリスト（種類・日付・数え方）、FC更新日
- **現場**：id、推しid（複数）、タイトル、日時、会場（自由文字）、現場の種類、ステータス、申込先、申込方法、名義、結果の通知元、締切のリスト（種類・日時・通知）、座席、同行者、写真のリスト、セトリ、感想
- **セトリの行**：順番、曲名、行の種類（曲／MC／EN／リハ／メドレー）
- **費用の行**：費目、金額、何人分、うち立替、回収済み
- **写真**：順番、圧縮コピー、サムネイル、元の画質（あれば）
- 保存先は端末内のデータベース。iOSがアプリを取り除いても消えない場所に置く
- バックアップは、データを1つのファイルに、写真は別に**追加分だけ**クラウドへ送る
- アップデートでデータの形を変えるときは、**変える前に自動でバックアップ**する

## 6. お金のもらい方

- **無料**：全機能。推しは何人でも、現場もいくらでも、写真も何枚でも。推しカラー（1色のテーマ、カレンダーの点、ウィジェットの色）も無料
- **買い切り（600〜800円くらい。ヒアリングで確かめる）「サポーターパック」**：
  - 追加のテーマ（推しカラー2色のグラデーション、季節のデザイン）
  - ウィジェットの追加デザイン、写真を入れられる大きいウィジェット
  - 年間まとめ画像の追加デザイン
  - アプリアイコンの変更
- **約束として決めておくこと**
  - 買い切りのまま。サブスクにはしない
  - 広告は出さない
  - 記録そのもの（推し・現場・写真の数）に制限をかけない
  - 推しカラーは有料側に移さない
  - あとから増えるデザインも、買った人には追加料金なしで届ける
  - 「購入を復元」で確実に戻せる

## 8. やらないこと

| やらないこと | 理由 |
|---|---|
| SNS・コミュニティ・推し友・クイズなどの交流機能 | 他のアプリで「使いづらくなった」「前に戻して」の原因になった |
| ログイン必須・サーバーへの保存 | ログアウトや機種変更でデータが消える原因になった |
| 広告（動画・リワードも）、サブスク、推し・現場・写真の数の制限 | ★1のいちばんの原因で、oshicase の売りの根っこ |
| 推しカラーの有料化 | 有料にしたアプリが強く嫌われた |
| みんなで共有するセトリ・会場データベース、外部サイトからの取得 | サーバーと運営が必要。外部サイトの規約や保守も重い |
| チケット販売サイトとの連携・当落の自動取得 | 公開の仕組みがない。壊れたときに「当落を見落とした」責任を負うことになる |
| 座席図の表示 | 会場図の権利と保守の負担が大きい |
| 運営からのお知らせ通知 | 「お知らせが多すぎる」への不満。通知は自分で入れたものだけ |
| 位置情報・アカウント連携の許可を求めること | 同意を求めただけで嫌われた例がある。許可は写真と通知だけ |

## 10. 気をつけること

- **権利**：推しの名前・写真はユーザーが入れるもの。アプリ側でアーティスト名やロゴ、公式画像は使わない。ストアの画像も架空の推しで作る
- **他社の名前**：説明文や広告で他社アプリの名前は出さない。「乗り換え歓迎」「データの書き出しができる」までにとどめる
- **「消えない」を本当にする**：アップデートのたびにデータ移行のテストを公開手順に入れる。復元も実機で確かめる
- **日数と金額の計算ミス**：1日のズレや合計の間違いは信頼を一気に失う。初日の扱い・うるう年・タイムゾーン・立替の差し引きは単体テストで固める
- **ウィジェットが止まる・黒くなる**：看板にするほど壊れたときの打撃が大きい。毎日の更新を実機で確かめる
- **機能を増やしすぎない**：いちばん褒められるのは「シンプルで使いやすい」。入力欄が増えても、必須はタイトルと日付だけを守る
- **写真の容量**：枚数は制限しない代わりに、圧縮・サムネイル・写真だけのバックアップのオン／オフで端末とクラウドの容量を守る
- **ウィジェットだけでは儲からない可能性**：だから中心は現場の記録に置き、ウィジェットは入口にする
- **作る前の確認**：現場によく行く人1〜3人にデモを触ってもらう。特に「分配開始日」「名義」「立替」が本当に使われるか、買い切りの値段がいくらならよいかを聞く（`reports/oshicase ヒアリング質問.md`）
- **調査の偏り**：根拠は App Store（iOS）のレビューに偏っている。Android と X の声は確かめられていない
