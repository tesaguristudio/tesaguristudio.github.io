# 消えない・邪魔しない・入金を流させないoshicaseへ

App Storeのレビュー2,286件と知恵袋・noteを読むと、推し活アプリの評価を一番下げているのは機能が足りないことではありません。**約束を破られること**です。★1の決め手になっているのは、アップデートや機種変更での**データ消失**、記録のたびに出る**広告**（誤タップや成人向け・詐欺広告を含む）、**買い切りからサブスクへの変更や無料枠の締め付け**、それに**起動できない・計算がずれる不具合**の4つでした。oshicaseの「広告なし・端末保存＋バックアップ・ログイン不要・推しは何人でも無料・買い切り」という骨組みは、この4つにほぼそのまま答えています。だから方針を大きく変える必要はありません。足すべきなのは主に2つです。1つめは**チケットの事故が起きる「当選→入金→発券・分配」の間を細かく扱うこと**。落選を一目で見分ける表示、分配開始日、名義、同じ日時の重複申込の警告などです。2つめは**ライブ記録で続けやすくするための入力の軽さ**です。最低限の項目だけで保存でき、会場は自由に書け、セトリは貼り付けて一括で入れられ、ツアーの公演は複製で作れるようにします。避けるべきなのは、SNS・コミュニティ機能への寄り道、ログイン必須、サブスク化、推しカラーの有料化、そして日数・金額の計算ミスです。ただし、根拠はApp Store（iOS）に偏っています。Google Playは調べておらず、知恵袋は検索結果の要約だけ、Xの生の投稿はほぼ取れていません。noteの記事の多くは競合の開発者が書いたものです。最後に、企画書への変更を「v1.0に入れる／後で／やらない」に分けて示します。

## 調べた範囲：iOSのレビューは全文、それ以外は断片

結論の確からしさは情報源ごとに大きく違います。先に範囲を示します。

| 情報源 | 読めた範囲 | 偏り・限界 |
|---|---|---|
| App Store（日本） | Appleの公開レビューRSSで28アプリ・**2,286件を全文**取得（1アプリ最大500件、新しい順）。うち★1〜3が494件、★4〜5で要望を含むものが749件。主なアプリの★1〜3と、ライブ記録系（Live Rock・relight・Ainy!）は全件を目視で確認 | 件数の多い老舗（シークログ487件、推して何日？480件）に集計が引っ張られる。2026年に出たアプリは数十件だけ（Ainy!は17件で、すべてリリース直後の★4〜5）。キーワードによる分類の精度は測っていない |
| Google Play | **対象外** | Android利用者の不満は分からない |
| Yahoo!知恵袋 | **検索結果に出る要約と投稿日だけ**。個別の質問ページは読めなかった | 要約は途中で切れていて、ベストアンサーの全文や回答の傾向は確認できていない |
| X（旧Twitter） | **生の投稿はほぼゼロ**。使えたのはnoteに埋め込まれた投稿とThreadsの1件だけ | 「Xで多い不満」は、ベンダーの説明から間接的に推測するしかない |
| note | 見つけた記事は全文を読んだ。ただし記事はWeb検索で見つけたもので、網羅的ではない | **多くはアプリやテンプレートの作者（＝競合）の宣伝記事**。「作った動機」に書かれた困りごとは実体験として使えるが、機能の評価は割り引いて読む必要がある |

この表から言えるのは、「何が★を下げるか」についてはiOSのレビューで量・質ともに強い根拠があるということです。一方、「チケット運用でどこで事故が起きるか」は知恵袋の断片とnoteの開発者記事が頼りで、一次情報としては薄めです。キーワード集計の件数は「写真」「カスタマイズ」のように不具合の話も拾ってしまうので、要望の強さの順位としてではなく、目安として読んでください。

## ★1を生むのは機能不足ではなく裏切りで、oshicaseの方針はそこに当たっている

★1〜3の494件を分類すると、最も多いのは**不具合（127件）**で、写真（92件）、カスタマイズ（77件）、ウィジェット（56件）、広告（52件）、課金（46件）、データ消失（44件）が続きます。主なアプリについて目視で確かめると、★1を決定づけ、そのまま利用をやめる理由になっているのは「データ消失」「広告」「課金方針の変更」「起動不能」でした。2024年以前と2025〜26年を比べると、★1〜3の総数はほぼ同じ（252件と242件）です。その中で**広告（20→32件）、データ消失（16→28件）、課金（19→27件）、プライバシー・ログイン（9→17件）**は最近のほうが増えています（[Apple レビューRSS](https://itunes.apple.com/jp/rss/customerreviews/page=1/id=1519067282/sortby=mostrecent/json)）。

データ消失の声は厳しいものです。「1年間推し活記録入れてたのに全部消えてんだけど」（[推して何日？ ★1 2026-01-06](https://apps.apple.com/jp/app/id1519067282)）、「機種変更したら三年分の記録が消えてしまった」（[シークログ ★1 2026-08-17](https://apps.apple.com/jp/app/id1603782312)）、そして「アップデートしたら記録していたものが全て消えました。デジタルに記録するとこういうことが起きるんですよね」（[レポブ ★1 2025-09-22](https://apps.apple.com/jp/app/id6502975294)）。レポブでは2025年9〜10月に同じ趣旨の★1が4件以上続いています。ログイン方式も原因になっています。レポブでは機種変更後に「新規登録ボタンしかなく、ログインボタンがない」、推しチェではログアウトしたらチェキが全部消えた、という報告がありました（[レポブ](https://apps.apple.com/jp/app/id6502975294)、[推しチェ](https://apps.apple.com/jp/app/id6752535744)）。「しばらく開いてなかったからアプリ取り除かれてて…ダウンロードしたらデータが全部消えてた」という声もあります（[推して何日？ ★2 2025-01-09](https://apps.apple.com/jp/app/id1519067282)）。iOSが使っていないアプリを自動で取り除いた後の挙動まで、ユーザーは「消えた」と受け止めています。

広告は、使い勝手を直接壊すうえに、不快な内容が嫌われています。「一つの項目を更新すると10秒程度の広告を見せられる…『アダルトサイトにアクセスしたため料金が発生しました』という詐欺広告も出てきた」（[記念日Today ★2 2026-06-09](https://apps.apple.com/jp/app/id1528469152)）。「日付を変えようとタップしたら…広告をタップしたことになって毎回サイトへ飛ぶ」（[推しPay ★1 2025-12-23](https://apps.apple.com/jp/app/id1523768983)）。知恵袋でも、推して何日？を入れたら「タップするとトータルセキュリティーというアプリをDLするように出てきました」という質問が451回閲覧されています（[知恵袋 q11318021736](https://detail.chiebukuro.yahoo.co.jp/qa/question_detail/q11318021736)）。推し活アプリそのものへの不満として知恵袋ではっきり拾えたのは、ほぼこれだけでした。

課金への反発の中心は、値段の高さではなく**方針の変更**です。「買い切り版のPro仕様を買っていました。アップデートされてからというものその時の経歴や名残が全て消えており、サブスクの入会を求められています」（[Live Rock ★1 2026-07-16](https://apps.apple.com/jp/app/id6758434262)）、「広告非表示だけの買い切りを残しておいて欲しかった」（[シークログ ★3 2025-03-16](https://apps.apple.com/jp/app/id1603782312)）。無料枠を絞ることへの反発も強く、推シラセには「無料プランだと推しを2人までしか登録できない…掛け持ちオタ➕学生だから厳しい」というレビューがあります（[推シラセ ★2 2026-10-17](https://apps.apple.com/jp/app/id6818704437)）。反対に、relightは「買い切りで広告が表示されない。機能追加や不具合解消がとても早く丁寧」と、乗り換えの理由として名前を挙げられています（[relight ★5 2026-03-23](https://apps.apple.com/jp/app/id6759641030)）。

もう1つ見落とせないのが、**運営の路線変更による肥大化**です。「会社が変わってからアプリ自体使いづらくなりました」（[推して何日？ ★1 2025-09-02](https://apps.apple.com/jp/app/id1519067282)）。「推しクイズや質問箱って推し活に必要なものなんでしょうか？」（[Oshibana ★3 2026-01-16](https://apps.apple.com/jp/app/id1581399897)）。「シンプルで使いやすい写真日記アプリだったので前の形に戻してほしい」（[Pics ★1 2025-07-20](https://apps.apple.com/jp/app/id1449001168)）。Oshibanaは、位置情報やYouTubeの閲覧履歴への同意を求めたことでも★1を受けています（[Oshibana ★1 2026-06-15](https://apps.apple.com/jp/app/id1581399897)）。★5で最も多い褒め言葉は「使いやすい・シンプル」（397件）なので、機能を足すこと自体がリスクになりえます。

ここから言えるのは、oshicaseの売り（広告なし、ログイン不要、バックアップ、推し無制限、買い切り）が、レビューで★1を生んでいる原因の裏返しになっているということです。ただし、これらは今や競合の多くが掲げる**標準装備**になりつつあります。relight・LIVE DIARY・推し活手帳などが同じことを掲げています（[note/nemuiasa](https://note.com/nemuiasa/n/nb9728056461e)、[note/thump_man](https://note.com/thump_man/n/ncfa806383410)、[note/infra_enge22](https://note.com/infra_enge22/n/n1a36ec17bf8a)）。看板に書くだけでは差になりません。差がつくのは「実際に消えない」「後から約束を変えない」を、実装と運営で示し続けられるかどうかです。

## チケットの事故は当選から入金・発券までの2週間に集中する

知恵袋で推し活の「管理」について多いのは、アプリのおすすめよりも、チケット運用のトラブル相談です。「一度支払いを流すとペナルティがついてしまうのでしょうか？」（[q11315679901](https://detail.chiebukuro.yahoo.co.jp/qa/question_detail/q11315679901)）、「初めて流してしまったのですが今後の当落に影響はでるでしょうか？」（[q12322900727](https://detail.chiebukuro.yahoo.co.jp/qa/question_detail/q12322900727)）のように、**入金を流したことへの不安**は2025〜26年にかけて繰り返し出てきます。ほかにも、こうした事故があります。

- 当選しているのを忘れて同じ時刻の別公演に申し込み、取り消せなくなった（[q10297032350](https://detail.chiebukuro.yahoo.co.jp/qa/question_detail/q10297032350)）
- 分配しようとしたら「チケットのお渡し期間は2026/11/1 12：00からです」と出た（[q11331929431](https://detail.chiebukuro.yahoo.co.jp/qa/question_detail/q11331929431)）
- bubbleの先行に申し込んだのに、結果はローソンチケットから届いた（[q13322482608](https://detail.chiebukuro.yahoo.co.jp/qa/question_detail/q13322482608)）
- 会員登録が必要だったのを見落としていて、応募履歴そのものがなかった（[q12324301282](https://detail.chiebukuro.yahoo.co.jp/qa/question_detail/q12324301282)）

1台の端末で複数の名義を管理していてよいか、という質問もあります（[q11313334136](https://detail.chiebukuro.yahoo.co.jp/qa/question_detail/q11313334136)）。どれも要約しか読めていませんが、事故の場所ははっきりしています。

noteのテンプレート配布者は、この構造を正確に言葉にしています。「申し込むのは各自、当たるのは誰か1人、払うのはその1人、行くのは全員。しかもこの間に2週間ほど空く」「事故はだいたい、発表日と支払期限の間で起きる」と書き、記録すべき項目として**公演名と日程、申込方法（抽選・先行・一般・リセール）、名義、当落発表日、支払期限、金額と何人分か**を挙げています。中でも「いちばん効くのは『名義』の列」だそうです（[note/oshi_money](https://note.com/oshi_money/n/n274f8cb58997)）。月に平均8現場という複数推しの書き手は、「抽選いつ発表だっけ？」「発券、いつから？」「FC更新、気づいたら切れてた」を「忘れたら詰むやつ」と呼んでいます（[note/bear05](https://note.com/bear05/n/n90a1bd058f1b)、開発者記事）。

App Storeにも、oshicaseの中心機能に直接重なる要望があります。relightには「抽選が外れた予定がそのまま残るのが当選の予定と見間違いしてしまうので…『落選』を追加・落選で上書き保存後に色が反転（もしくはグレー…）」という要望があります（[relight ★5 2026-05-25](https://apps.apple.com/jp/app/id6759641030)）。推しROOMには「グッズ発売日やチケット当落、支払い等を登録出来る項目があると嬉しい」という声があります（[推しROOM ★5 2026-09-14](https://apps.apple.com/jp/app/id6788812583)）。専用の道具がないので、受付期間や当落の日付のスクショをメモアプリに残している人もいます（[シークログ ★5 2024-04-04](https://apps.apple.com/jp/app/id1603782312)）。

企画書のステータス（検討中→申込済→当選/落選→入金済→発券済→参戦済）と締切通知は、この悩みの中心に当たっています。ただし、事故を防ぐには項目が足りません。特に足りないのは**分配開始日、名義、申込先と結果の通知元、同じ日時に当選済みの現場があることの警告、落選カードの見た目の区別**です。もう1つ注意点があります。申込→当落→入金→発券を段階ごとに通知するアプリは推しごよみや推シツジなどすでに複数あり、推シツジは「入金を忘れて席が消える」ことを防ぐのを看板にしています（[AppBank](https://www.appbank.net/2026/08/18/iphone-news/3081173.php)）。ステータス管理そのものは差別化になりません。oshicaseの強みは、このステータスが写真・セトリ・感想・費用と**同じ1枚のカードに続いていて、落選まで含めて記録として残る**ことです。noteにも「落選も消さずに残しておく。…『この先行は全滅だったから、次は一般も張ろう』という相談が、記憶ではなく記録でできる」とあります（[note/oshi_money](https://note.com/oshi_money/n/n274f8cb58997)）。

## ライブ記録の利用者は入力の軽さとセトリの細かさを求めている

2026年に出たライブ記録アプリ（Live Rock・relight・Ainy!）のレビューは★4〜5が大半です。要望は**入力の手間を減らすこと**と**入力項目の細かさ**の2つに集中しています。手間については、「これまでのライブを一つ一つ全て登録していくのがかなり大変…プレイリストからセットリストをインポート、もしくはコピペでの一括入力」（[Live Rock ★4 2026-07-15](https://apps.apple.com/jp/app/id6758434262)）という声があります。評価されているのは、チケットやセトリの画像から自動で入力してくれること（[relight ★5 2026-05-14](https://apps.apple.com/jp/app/id6759641030)、[Ainy! ★5 2026-11-19](https://apps.apple.com/jp/app/id6795072297)）です。ただし、最も印象的な褒め言葉は自動化ではなく**最低限の入力**についてのものでした。「アーティスト名とライブ名、日付と会場だけ入れればとりあえず保存できるのも助かる。後からセトリや画像を足していってます。めんどくさがりですが、これなら記録し続けられそう」（[relight ★5 2026-03-20](https://apps.apple.com/jp/app/id6759641030)）。

細かさについては、セトリにMC・アンコール・リハ・メドレーの区別がほしいという声が、Live Rockとrelightでそれぞれ5件以上ありました（[Live Rock ★4 2026-05-13](https://apps.apple.com/jp/app/id6758434262)、[relight ★4 2026-03-19](https://apps.apple.com/jp/app/id6759641030)）。会場については、選択肢から選ぶ方式が記録そのものを妨げています。「Zepp Tokyoなどのなくなった会場や…特設会場を選択できないのが辛い…会場が必須なので、ライブ記録が出来ない…自由記述だと嬉しい」（[Live Rock ★4 2026-03-22](https://apps.apple.com/jp/app/id6758434262)）。ほかにも、出演者が発表される前のフェスを登録できない、サーキットイベントで会場を複数入れたい、という要望があります（[relight](https://apps.apple.com/jp/app/id6759641030)）。現場の種類として、番組観覧・特典会・ライブビューイング・舞台も求められています（[Live Rock ★5 2026-04-12](https://apps.apple.com/jp/app/id6758434262)、[relight ★5 2026-04-19](https://apps.apple.com/jp/app/id6759641030)）。

複数推しの扱いでは、oshicaseの設計がすでに当たっています。共演した現場を推しごとに入力し直さなくてよいことが、推しライフで評価されています（[推しライフ ★4 2026-09-29](https://apps.apple.com/jp/app/id6781992151)）。箱推しやグループを行き来する人には、推しごとにページが分かれている設計が向いていません（[Live Rock ★3 2026-03-20](https://apps.apple.com/jp/app/id6758434262)）。企画書の「現場：推しid（複数）」は正しい判断で、UIでも1枚のカードに複数の推しを付けられることをはっきり見せるべきです。写真については、「フェスは写真が多くなりがち」なので枚数を増やしてほしいという要望と（[relight ★5 2026-03-23](https://apps.apple.com/jp/app/id6759641030)）、写真の「順番バラバラになる」への★1があります（[Pics ★1 2024-12-23](https://apps.apple.com/jp/app/id1449001168)）。企画書の「何枚でも」に加えて、**並び順を保つこと**が必須です。

ここから導ける設計方針は、**必須項目は「タイトル」と「日付」だけにし、それ以外はすべて後から足せるようにする**ことです。会場は自由記述（候補は過去の入力から出す程度）、出演者は空欄でもよい、ツアーの別公演はカードの複製で作る、セトリはテキストを貼り付けると1行1曲に分かれて行の種類を後から付けられる、という形です。これはOCRやURLからの自動入力よりずっと安く作れて、「続けられる」という最も強い褒め言葉に直結します。自動入力は評価されていますが、精度が低いと「URLからの自動入力が使えない…ことが多い」という不満に変わります（[relight ★3 2026-03-22](https://apps.apple.com/jp/app/id6759641030)）。v1.0で無理に入れる必要はありません。

## お金は「見たいが見られたくない」から、表示オフは根拠のある機能

知恵袋のお金の相談は、管理ツールの使い勝手ではなく**罪悪感と、身近な人に知られたくない気持ち**が中心です。「推し活で使っていることを親は知らない」（[q13316963013](https://detail.chiebukuro.yahoo.co.jp/qa/question_detail/q13316963013)）、「唯一親にバレずにお金を貯めれるのがPayPayだけ」（[q13318447753](https://detail.chiebukuro.yahoo.co.jp/qa/question_detail/q13318447753)）、夫に頼むのが「とても、罪悪感があり頼みづらくストレス」（[q10315734490](https://detail.chiebukuro.yahoo.co.jp/qa/question_detail/q10315734490)）。パートナー側から「金銭面的に耐えられません」という相談も出ています（[q14307110494](https://detail.chiebukuro.yahoo.co.jp/qa/question_detail/q14307110494)）。App Storeでは、relightの利用者が「積み上がった金額に恐怖を覚える。(非表示にできます！)」と、隠せることを褒めています。シェア画像にセトリや金額を「載せる／載せないを選びたい」という要望もあります（[relight ★5・★4 2026-03](https://apps.apple.com/jp/app/id6759641030)）。その一方で、「どれだけお金使ったかとかわかるとちょっと今月はやめようとかなれる」という見える化の価値も語られています（[推シラセ ★5 2026-10-17](https://apps.apple.com/jp/app/id6818704437)）。

企画書の「金額を表示する（オン／オフ）」と「まとめ画像に金額を入れる（オン／オフ）」は、この二面性にきちんと応えています。強めるなら、**まとめ画像やシェア画像の金額は最初からオフにしておく**ことです。共有にはもう1つ摩擦があり、リア垢で参戦記録を載せて「マウントウザイ」と言われた、監視されているようで怖い、という相談があります（[q10295390885](https://detail.chiebukuro.yahoo.co.jp/qa/question_detail/q10295390885)、[q11331534956](https://detail.chiebukuro.yahoo.co.jp/qa/question_detail/q11331534956)）。金額だけでなく、**座席や回数も画像から外せる**ようにしておくと安心です。

費用の項目では、企画書にない具体的な要望が1つあります。立替です。noteでは「人のぶんを含めた金額をそのまま支出欄に入れると、年間の集計が実態より膨らむ。私は金額の横に何人分かを書いておいて、自己負担だけを集計に回している」（[note/oshi_money](https://note.com/oshi_money/n/n274f8cb58997)）と書かれています。連番や同室ホテルの立替を「誰から回収したか曖昧になる」という悩みも挙がっています（[note/juicy_flea4007](https://note.com/juicy_flea4007/n/n048bea0881cd)）。費用の行に**「何人分」か「うち立替」と、回収済みのチェック**を持たせ、集計は自己負担分だけにする。これはデータの形を後から変えると移行時にデータ消失のリスクを生むので、v1.0の時点で入れておく価値があります。費目には、交通費・宿泊費が実際に求められています（[Live Rock ★5 2026-05-31](https://apps.apple.com/jp/app/id6758434262)）。チケットの手数料も分けておくと、「チケット代」の実態に近くなります。

## 記念日とウィジェットは、1日のズレと遅い通知で信頼を失う

推し活の記念日アプリで最も長く続いている不満は、**日数の1日ズレ**です。「『初日を含めずカウント』をオフにすると『記念日まであと○日』のカウントがズレてる。ずっと直らない」（[推して何日？ ★2 2025-05-08](https://apps.apple.com/jp/app/id1519067282)）、「うるう年があったので、1日ズレて表示される」（同 ★3 2024-03-17）。金額の計算でも、電卓で49,664円のところが332,606円と表示された、という報告があります（[MeMory ★3 2026-10-22](https://apps.apple.com/jp/app/id6761535318)）。推して何日？には「通知来なくなりました。大切な記念日を逃しました。もう二度と使いません」（★1 2026-02-21）という声もあります。さらに、通知が「その日の終わり23時とかに来るから見逃してしまう…午前中には通知が来て欲しい」（★3 2024-09-07）、運営からの「お知らせが多すぎる」（★1 2026-09-05）という不満もあります（[推して何日？](https://apps.apple.com/jp/app/id1519067282)）。

ウィジェットは、看板にするほど壊れたときの打撃が大きくなります。Oshibanaでは、2023年12月〜2024年9月にウィジェットが黒や白になるという報告が10件以上ありました（[Oshibana ★1 2023-12-20 ほか](https://apps.apple.com/jp/app/id1581399897)）。推しスケには「昨日の予定から更新されなくなりました」という声があります（[推しスケ ★2 2026-02-22](https://apps.apple.com/jp/app/id1573710956)）。それでも需要は本物です。ライブ記録系では「次回参加のLIVE公演のカウントダウン」（[Live Rock ★5 2026-05-30](https://apps.apple.com/jp/app/id6758434262)）、「ホーム画面やロック画面にも」（[relight ★4 2026-03-18](https://apps.apple.com/jp/app/id6759641030)）が求められています。Oshibanaの★5では、ウィジェットとホーム画面への言及が87件と最も多くありました。

oshicaseにとっての含意は、記念日ウィジェットの価値が「日数が正しいこと」と「毎日きちんと更新されること」で決まり、デザインの種類は二の次だということです。v1.0では次のものを、テストで固めたうえで出すべきです。

- 日数計算の選択肢：初日を含める／含めない、「◯日」表記と「◯年◯か月」表記、ちょうど◯年の日は「4年」と出す
- うるう年とタイムゾーンの扱い
- 通知時刻の指定（初期値は朝）
- ロック画面の小さなウィジェット

運営からのお知らせ通知は、そもそも送らない方針でよいでしょう。企画書の「締切は自分が入れたものだけ通知」はこの不満と合っているので、FC更新日のような推し単位の期限も同じ仕組みで扱えるようにします。

## 推しカラーは無料のまま、買い切りの約束は文章で固定する

課金の設計では、2つの事例が判断の基準になります。1つは、Picsが推しカラーを有料にして「『推しカラー💜を使うなら課金💸しろ』ですって⁉️」という★1を受けたことです（[Pics ★1 2025-12-16](https://apps.apple.com/jp/app/id1449001168)）。もう1つは、Live Rockが買い切りProからサブスクに移った後に★1を受けたことです（[Live Rock ★1 2026-07-16](https://apps.apple.com/jp/app/id6758434262)）。企画書では、推しカラー1色のテーマは無料、2色のグラデーションや季節のデザインはサポーターパック、となっています。この線引きは安全です。推しカラーそのもの（テーマ色・カレンダーの点・ウィジェットの色）は、今後も**絶対に有料側へ移さない**と決めておくべきです。

サポーターパックについては、3つを最初から約束しておくのがよいでしょう。「購入を復元」で確実に戻せること、ストアの説明文に「買い切り。サブスクにはしません」と明記すること、将来の追加デザインも購入済みの人には追加料金なしで届けること、です。値段（600〜800円）が妥当かどうかを判断できる金額の言及は、レビューにはほとんどありませんでした。推シラセの月額480円／980円への不満が唯一の手がかりです。relightの「お手軽な値段かつ買い切りで課金へのハードルが低い」（[relight ★5 2026-08-13](https://apps.apple.com/jp/app/id6759641030)）から分かるのは、受け入れられているのが買い切りという形式だということで、具体的な価格の根拠にはなりません。

Oshibanaからの乗り換え層については、レビューから取れた情報は限られます。閲覧専用化に直接触れたレビューは6件ほどで、「データ書き出しの進行度が0％のまま30分以上経っても進まず困っています」（[Oshibana ★4 2026-08-30](https://apps.apple.com/jp/app/id1581399897)）という声がある程度です。移行先のアプリ名を挙げたレビューは見つかりませんでした。乗り換えを呼びかけている他社のOshiNowも「アプリ固有のデータ形式はそのまま持ち込めません」として、手作業での再登録を案内しています（[oshinow.com](https://oshinow.com/oshibana-migration)）。書き出し形式が分からないまま取り込み機能に工数をかけるのは割に合いません。むしろ、**推しの登録が1分で終わる**ことのほうが、乗り換える人には効きます。

## oshicase企画への変更：v1.0に入れる／後で／やらない

以上をまとめて、企画書（v1.0〜v1.2）への具体的な変更を優先度順に並べます。「根拠」は、その変更を支える主な声です。

### v1.0に入れる（公開前に必須）

| # | 変更 | 根拠 | 企画書との差分 |
|---|---|---|---|
| 1 | **データ移行の前に自動でバックアップ＋「最終バックアップ日時」を表示＋復元を実際に確認できる画面**。データベースのデータは消されない場所に置き、アップデート時の移行テストを公開手順に入れる | データ消失が★1の最大要因（レポブ・シークログ・推して何日？・Live Rock） | バックアップはあるが、「消えない」を確かめる仕組みがない |
| 2 | **落選カードをグレー表示にして「これから」の一覧で当選と見分けられるようにする。ステータスに「見送り」「譲渡・取消」を追加** | relightへの落選表示の要望、知恵袋の入金を流した相談 | 落選はあるが、見た目の区別と終わり方の種類がない |
| 3 | **締切の種類に「分配開始」「FC更新」を追加**。カードに**名義**、**申込方法（抽選／先行／一般／リセール）**、**結果の通知元**の欄を足す | 知恵袋の分配期間外・通知元の混乱、noteの「名義の列がいちばん効く」 | 締切は申込・当落・入金だけ |
| 4 | **同じ日時の公演が当選済み・申込済みのとき、申込時に警告する** | 当選を忘れて重複申込した相談（q10297032350） | なし。作りやすく、事故防止の訴求になる |
| 5 | **必須項目はタイトルと日付だけ**。会場は自由記述（過去の入力から候補を出す）、出演者は空欄可、**カードの複製**（ツアー・複数公演用） | relight「とりあえず保存できる」、Live Rockの会場が選べない不満 | 必須項目と複製が決まっていない |

| 変更 | 時期の目安と理由 |
|---|---|
| 年間まとめ画像・まとめ画面・予算 | 企画どおりv1.1、年末に合わせる。競合も持っている標準機能なので、差はデザインと「金額を出さない」作りでつける |
| チケットやセトリのスクショからの自動入力（端末内の文字認識） | v1.2以降。評価は高いが、精度が低いとかえって不満になる。まず貼り付けで十分か確かめる |

| 標準カレンダーへの書き出し | 前回の調査で提案したもの。既存のカレンダーの使い方を壊さないための機能 |
| 都道府県・会場別の集計、「この曲を何回聴けたか」 | Ainy!の地図やLive Rockの曲別回数が★5で評価されている。データの形（会場・セトリ行）を先に整えておけば、後から足せる |
| Oshibanaの書き出しZIPの取り込み | 形式が確認できてから。現時点では他社も取り込めておらず、工数に見合う根拠がない |

### やらない

| やらないこと | 理由 |
|---|---|
| SNS・コミュニティ・推し友・クイズなどの交流機能 | 推して何日？・Oshibana・Picsで「肥大化」「前に戻して」の★1を生んだ |
| ログイン必須・サーバーへの保存 | レポブ・推しチェでのデータ消失の原因になった |
| 広告（動画広告やリワード広告も含む）、サブスク、推しや現場の数の制限 | ★1の主因で、oshicaseの売りの根っこ |
| 推しカラーの有料化 | Picsの★1 |
| みんなで共有するセトリ・会場データベース、LiveFansなど外部サイトからの取得 | サーバーと運営が必要。外部サイトの規約や保守の負担も大きい |
| チケット販売アプリとの連携・当落の自動取得 | 公開APIがなく、壊れたときに「当落を見落とした」責任をアプリが負うことになる |
| 座席図の表示 | 会場図の権利と保守の負担が大きい（Live Rockへの要望はある） |

## Conclusion

今回の調査で見方が変わったのは、ユーザーが求めている中身が「新しい機能」ではなく「**今あるものが明日も同じように動くこと**」だという点です。★1の文面に出てくるのは、消えた記録、変わった課金、増えた広告、ずれた日数、戻してほしい旧仕様、とすべて「変化」への怒りです。ここから、oshicaseのv1.0は機能の数よりも、データの形と約束を最初に正しく決めることのほうが重要だと言えます。費用の立替、セトリの行の種類、締切の種類、名義をデータの形として先に持っておけば、後から機能を足すときにデータ移行のリスクを負わずに済みます。中心の訴求は「入金を流さない」と「落選も記録に残る」の2本に絞れます。この2つは知恵袋の実際の事故と、noteの記録の使い方の両方に根拠があり、競合の「締切通知」とは違って、記録帳のアプリだからこそ言えることです。

残る不確実性は、Androidの利用者と、Xでの生の声です。特に、元Oshibanaの利用者がどこへ移ったのか、入金忘れの声が実際にどのくらい多いのかは、今回のデータでは確かめられていません。公開前の確認では、企画書にあるとおり現場によく行く2〜3人にカードの項目を見てもらいましょう。そのとき「分配開始日」「名義」「立替」の3つが本当に使われるかを聞くのが、最も安く確実な検証になります。
